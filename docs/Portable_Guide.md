# Запуск на ноутбуке без Unreal Engine

Готовая игра: **PredictionLab_Windows.zip** из [GitHub Release v1.0.0](https://github.com/5hleev/unreal-client-side-prediction/releases/tag/v1.0.0).
Распаковать архив целиком, затем следовать инструкции ниже.

Перенести **всю папку `prac_4/dist/Windows`**, включая вложенные Engine и PredictionLab.
Это самостоятельная Windows x64 сборка Development: редактор Unreal и Visual Studio
для запуска не нужны. Подпапка Engine здесь содержит только компоненты готовой игры,
а не полный установленный редактор UE.

1. Распаковать/скопировать папку на локальный диск ноутбука с Windows.
2. Если Windows сообщает об отсутствии компонентов Visual C++, выполнить
   `Engine/Extras/Redist/en-us/vc_redist.x64.exe` из этой папки.
   Для ошибки GameInput есть `GameInputRedist.msi` в той же папке.
3. Дважды нажать `Start_Clean.bat`. Откроются два окна: хост слева и клиент справа.
4. Щёлкнуть по нужному окну. WASD — движение, мышь — камера, Shift — спринт,
   Space — прыжок, F2 — режим предсказания, F3 — учебный серверный запрет.
5. Закрыть **оба** окна перед запуском следующего профиля.
6. Для сравнения с задержкой запустить `Start_Lag100.bat`.
   Для задержки и потерь — `Start_Loss175.bat`.
7. В окне клиента показать F2 OFF/ON и различие времени реакции в HUD.
   F3 без Shift → ждать 1 с → W + Shift показывает отказ/коррекцию.
   Повторный F3 снимает запрет. Для выхода — Alt+F4 в обоих окнах.

Если клиент не успел подключиться, нажать `~` и ввести `open 127.0.0.1:7777`.
При первом запросе Windows Firewall разрешить локальное взаимодействие приложения.
Для этого сценария интернет не требуется: оба процесса соединяются через localhost.
Если служебное предупреждение освещения (`Lighting needs to be rebuilt`,
`DumpUnbuiltLightInteractions`) перекрывает HUD, в консоли каждого окна выполнить
`DisableAllScreenMessages`. Это скрывает служебные экранные сообщения;
наш HUD с Response продолжает рисоваться. Освещение этой командой не пересчитывается.
В обновлённом tools/launch_portable.ps1 добавлен -NoScreenMessages для обоих процессов.
Для уже перенесённой игры достаточно заменить launch_portable.ps1 рядом с exe
обновлённым файлом из tools, пересборка игры не требуется.
Если ноутбук не справляется с двумя окнами, в launch_portable.ps1 можно уменьшить
ResX/ResY; заранее проверить фактическую производительность на ноутбуке.

Для показа исходников и отчёта дополнительно перенести `Prac_4.zip` и PDF.
Если преподаватель требует именно редактор UE/PIE, понадобится установленный UE 5.8
и инструменты C++; самостоятельная игра показывает поведение, но не интерфейс редактора.

На текущем компьютере Intermediate, Saved и dist — ссылки на `F:/UE_Prac4_Build`:
это сделано из-за заполненного диска C:. Для ноутбука копировать **содержимое папки
Windows или отдельный переносимый ZIP**, а не сами ссылки на папки.

Повторно собрать игру на компьютере разработки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package_windows.ps1 -EngineRoot 'F:\Epic Games\UE_5.8'
```

Используется Development, чтобы сохранить консоль, эмуляцию сети и диагностические
маркеры. Shipping для этой учебной демонстрации не подходит.
